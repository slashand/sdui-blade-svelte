# 1.1.0 release record

Core and Svelte share stable version `1.1.0`. This is a minor release because Core adds a public browser-history coordinator and a `close` action to the SDUI contract. It is not a silent patch bump from the local `1.0.2` manifests.

Both package manifests use version `1.1.0`. Svelte's release guard checks the stable package version and an exact Core `1.1.0` dependency in the manifest and frozen lockfile. The GitHub `v1.1.0` tag remains a source record; future GitHub Releases do not trigger npm publication.

Core `1.1.0` was published to npm before Svelte's dependency was pinned. The Svelte lockfile records the registry integrity for that exact Core archive. React and Angular releases are separate and are not part of this release.

The frozen-install supply-chain policy normally waits 24 hours before accepting new packages. `pnpm-workspace.yaml` excludes only the verified Core `1.1.0` release so that Svelte can publish in the same release window; the exact archive integrity remains pinned in the lockfile.

The release sequence is Core first, then Svelte. For a future unused version, run `npm run publish:latest` in the Svelte checkout after pinning the published matching Core version and updating the frozen lockfile. The command rejects an already-published version, checks npm login, builds, runs `svelte-check` and lint, then publishes the built package directly to npm under `latest`. Complete the browser-based npm two-factor challenge when prompted. If Core was published less than 24 hours earlier, update the exact `minimumReleaseAgeExclude` entry for that reviewed Core version. A local publish cannot generate cloud CI provenance. Verify npm version, `latest`, and archive integrity after publication. Browser qualification remains owner-run because demo servers are not started by this release operator.
