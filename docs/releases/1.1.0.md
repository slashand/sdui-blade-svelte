# 1.1.0 release preparation

Core and Svelte share the proposed stable version `1.1.0`. The last stable GitHub tag in each repository is `v1.0.0`. This is a minor release because Core adds a public browser-history coordinator and a `close` action to the SDUI contract. It is not a silent patch bump from the local `1.0.2` manifests. npm already contains Svelte `1.0.1` and `1.0.4-alpha.7`; neither is the matching Core/Svelte stable release.

Current source branches are `fix/stable-package-qualification` in both repositories. The candidate has not been committed, tagged, published, or installed by a hosted consumer. Both package manifests use version `1.1.0`; Core's release guard requires tag `v1.1.0`, a matching package and lockfile version, and a stable version number. Publishing a GitHub Release triggers npm publication; a tag alone does not.

Core `1.1.0` is not yet in npm. Svelte's manifest and frozen lock therefore still use the last available Core alpha while its own package version is `1.1.0`. This keeps local frozen installs valid. It does not make the Svelte package a final release candidate: its exact Core dependency, registry integrity and lockfile must be resolved and reviewed after Core publication. No unpublished dependency or invented registry integrity is committed.

After review, merge Core's candidate, create its annotated `v1.1.0` tag on the exact reviewed commit and publish its GitHub Release. Confirm the Core workflow, npm version, `latest` distribution tag and archive integrity. Then pin Svelte's Core dependency to exact `1.1.0`, resolve and review its registry lock, run a frozen install and repeat its full package and owner-run browser qualification. Merge and tag that exact Svelte commit `v1.1.0`, publish its GitHub Release, and verify the workflow and npm archive integrity. React and Angular releases are separate; do not tag them at a mismatched version.

Local preparation evidence on November 20, 2026: Core 56/56 tests, clean build and package dry-run passed; its package contains current ESM output without stale `.cjs` files. Svelte's source passed the direct `svelte-check` binary with zero diagnostics, production build, `svelte-package`, `publint`, and a package dry-run. These Svelte checks used the currently installed Core alpha; they do not qualify the unpublished Core `1.1.0` combination. The `pnpm check` wrapper attempted to purge the existing `node_modules` without an interactive terminal and stopped before the check; the direct binary check passed without changing that directory. No app server or browser suite was started during this preparation. The official Svelte autofixer reported two lint-rule resolution issues and existing advisory effect suggestions in `BladeHost.svelte`; this release-preparation change did not edit that component.
