## The SDK owns close chrome

The native X can now receive four optional props:

| Prop              | Contract                                                                                                        |
| ----------------- | --------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `onCloseRequest`  | `() => void                                                                                                     | Promise<void>`. The consumer owns confirmation and the final engine close. The SDK never dismisses automatically after the callback resolves. |
| `closeDisabled`   | Blocks X activation while consumer work cannot be interrupted.                                                  |
| `closeLabel`      | Accessible localized button label. Default: `Close blade`.                                                      |
| `closeErrorLabel` | Localized recoverable alert if the callback throws/rejects. Default: `Unable to close blade. Please try again.` |

Use the SDK X rather than hiding it and supplying an application replacement.
The consumer still provides workflow content and guard logic; data loss cannot
be decided by presentation chrome alone. A callback can show a confirmation and
return without closing, or await an async decision. A positive explicit decision
closes the exact invocation through the engine. Keep any core dirty-state check
and apply force only under the application's reviewed discard/completion rule.

```svelte
<Blade
	{bladeId}
	title={documentTitle}
	onCloseRequest={requestClose}
	closeDisabled={saving}
	closeLabel={labels.close}
	closeErrorLabel={labels.closeFailed}
>
	{@render documentContent()}
	{#snippet footer()}
		<button class="document-save-action" type="button" onclick={saveDocument}>Save</button>
	{/snippet}
</Blade>
```

The snippet illustrates API placement; its labels and functions belong to the
consumer. No tenant-authored executable callback, permission, provider or private
state is serialized into the package contract.

Pending callbacks coalesce native close attempts. The X retains its dimensions,
shows a centered inline spinner and exposes `aria-busy`; reduced-motion settings
disable spinner animation. Rejection retains the blade, displays the supplied
error and permits retry. A detached invocation cannot publish an old rejection
into newly mounted content. The SDK does not force-close after the callback and
therefore cannot close an unrelated blade that became topmost during the decision.

If `onCloseRequest` is absent, native closing preserves the old behavior: close
the specified blade, or the top blade when no ID was supplied, through existing
core dirty checks. No default forced dismissal was added. Existing class/snippet
overrides remain supported, including an existing `hidden` close class. Consumers
can migrate incrementally; they must not retain two visible close controls.

This callback handles the native X only. Escape, navigation, Back/Forward,
backdrop actions, close-all and browser unloading must retain their own current
guards and, where appropriate, reuse the consumer's close decision. This release
does not promise an engine-wide asynchronous interception system or weaken host
history. Modal focus/background isolation remains the consumer's established
integration requirement.

## Footer and theming

The SDK footer is a fixed flex region outside the body, with wrapping actions,
left alignment and a configurable `--sdui-footer-gap` (default `0.5rem`). Place
actions in the `footer` snippet, not inside the document scroll area or another
application-authored imitation of the footer. Body/header/host geometry and header
resize observation are unchanged.

Chrome CSS is shipped in `dist/blade-chrome.css` and imported by Blade, with package
CSS side effects preserved. Close styling uses CSS variables and inherits text
when no theme value is supplied. Coarse pointers have a minimum 44px target.
Explicit consumer classes remain available for a reviewed presentation override.
The native default footer now left-aligns direct children; review any consumer
that previously relied on their inline placement or a custom right-aligned area.
